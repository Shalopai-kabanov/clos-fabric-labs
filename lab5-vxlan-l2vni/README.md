# Лабораторная работа №5

# VXLAN EVPN. L2 VNI

## Цель

Настроить Overlay сеть на основе VXLAN EVPN для обеспечения L2-связности между клиентами, подключенными к разным Leaf-коммутаторам.

## Схема стенда

Топология сети представлена на схеме `Topology.png`.

В качестве Underlay используется eBGP, настроенный в предыдущей лабораторной работе.

В качестве Overlay используется EVPN поверх VXLAN.

## План работы

1. Настроить eBGP Underlay между Spine и Leaf.
2. Настроить BGP EVPN peering между Leaf и Spine.
3. Настроить Loopback1 в качестве VTEP-адреса.
4. Создать VLAN 10 для клиентского сегмента.
5. Настроить L2 VNI 10010.
6. Настроить распространение MAC-адресов через EVPN.
7. Проверить VXLAN-туннели между Leaf-коммутаторами.
8. Проверить связность между клиентами.

# Проверка работы

## Проверка EVPN соседств

Leaf1:

```bash
show bgp evpn summary
```

Вывод:

```text
Neighbor      AS      State   PfxRcd
10.0.0.2      65000   Estab   6
10.0.0.14     65001   Estab   6
```

EVPN-соседства успешно установлены через оба Spine-коммутатора.

---

## Проверка распространения MAC-адресов

Leaf1:

```bash
show bgp evpn route-type mac-ip
```

Вывод показывает получение MAC-адресов удалённых клиентов через EVPN:

```text
0c47.d727.0000
0c9c.8778.0000
0cd8.1fdc.0000
0ce0.9751.0000
```

На Leaf2 также получен MAC-адрес клиента с Leaf1:

```text
RD: 100.100.100.1:10010 mac-ip 0ce0.9751.0000
```

Это подтверждает корректное распространение EVPN Type-2 маршрутов.

---

## Проверка IMET маршрутов

Leaf1:

```bash
show bgp evpn route-type imet detail
```

Получены IMET маршруты от всех удалённых VTEP:

```text
Tunnel ID: 100.100.100.2
Tunnel ID: 100.100.100.3
Tunnel ID: 100.100.100.4
```

Также присутствуют:

```text
TunnelEncap:tunnelTypeVxlan
VNI: 10010
PMSI Tunnel: Ingress Replication
```

Это подтверждает корректную работу EVPN Type-3 маршрутов.

# Особенности реализации

Во время настройки было обнаружено, что в версии vEOS-lab 4.33.1.1F автоматическое формирование VXLAN Flood List на основании EVPN IMET-маршрутов не выполнялось.

Для корректной передачи BUM-трафика (Broadcast, Unknown Unicast, Multicast) на каждом Leaf-коммутаторе был настроен статический список удалённых VTEP:

```bash
interface Vxlan1
   vxlan flood vtep ...
```

После настройки Flood List VXLAN-туннели были успешно сформированы и появилась связность между клиентами.
